# 亲密关系与沟通

来源：love-skill。使用其事件梳理、双视角、关系循环、沟通练习与修复方法。

先了解发生了什么、用户的感受与目标、是否反复出现。只有一方材料时，把对方体验写成待核实的可能性，不代对方陈述事实。不要强制分析性别，不用“永远中立”淡化伤害或胁迫。

普通冲突可按需要采取：降温并约定重新沟通 → 区分观察、解释、感受与需求 → 复述核对 → 描绘触发与回应的循环 → 提出一个具体、可拒绝的请求或边界 → 检查实施后的效果。暂停长度依情境，不以心率阈值诊断状态。不替用户发送消息、预约或安排提醒。

按问题加载少量材料：
- 沟通表达：[NVC](../upstream/love/frameworks/nvc.md)。
- 反复争吵：[依恋](../upstream/love/frameworks/attachment-theory.md)、[冲突处理](../upstream/love/protocols/conflict-resolution.md)。依恋是待检验视角，不是固定标签。
- 信任修复：[修复协议](../upstream/love/protocols/emotional-repair.md)。修复需自愿；不要求受伤方原谅或继续关系。
- 读心、绝对化解释：[认知方法](../upstream/love/frameworks/cbt-couples.md)。验证具体想法，不否定情绪。
- 看不到对方视角：[视角练习](../upstream/love/protocols/perspective-shift.md)。理解不等于承担不属于自己的责任。
- 需要更详细方法时见 [完整原文索引](../upstream/love/original.txt) 的 frameworks 与 protocols；这些路径相对于 upstream/love/。

输出优先简明：当前矛盾、可能循环、仍未知的部分、一个可尝试的表达。根据用户要求增加双人分析或练习，不默认输出全部框架。上游的神经机制、比例、时间阈值和疗效断言须独立核实后使用；避免将性别、身体感受或模型推断视为因果证明。
